# Lostlink Project Context

## Purpose

Keep work aligned with LostLink product, team, and trust boundaries.

## Trigger

Use for cross-service features, ambiguous scope, roadmap planning, or changes touching matching and claims.

## When Not To Use

Skip when a narrower skill and an explicit task envelope fully cover the change.

## Inputs

Read `AGENTS.md`, the task scope guard, relevant architecture docs, and current status.

## Workflow

1. Confirm owner, sub-scope, writes, forbidden areas, dependencies, and pass/fail signals.
2. Locate the smallest affected path from web through Go to data, storage, or AI.
3. Separate public matching data from restricted ownership-verification evidence.
4. Select only specialist skills whose triggers apply.

## Rules

- Do not start adjacent roadmap tasks or perform unrelated cleanup.
- Keep Go authoritative for workflows and authorization.
- Treat similarity as discovery evidence, never ownership proof.
- Preserve human review and approval.

## Verification

Compare the final diff with allowed writes, required contracts/checks, and acceptance criteria.

## Outputs

Produce a scoped plan or change with exact skills loaded, evidence, risks, and handoff needs.
